Notas de implementação — Bubble Tea
Modelo puro
O modelo é redutor puro sobre o log de eventos; a View é pura sobre modelo + geometria. tea.WindowSizeMsg só atualiza a geometria — nenhum teste precisa de terminal.
Composição
JoinVertical para status / fluxo / trabalho / entrada e JoinHorizontal para fluxo + painel. Largura do painel = clamp(16, w/4, 34), escondido abaixo de 100 colunas salvo preferência explícita.
Bubbles
viewport no fluxo (AtBottom() decide se acompanha), textinput na entrada, spinner (Dot) no status e na linha de trabalho, help para o `?`. O modal é overlay desenhado por cima, com Update curto-circuitando toda tecla.
Largura medida
Toda medida em células com escapes descontados (lipgloss.Width / runewidth) — estilo nunca altera largura, senão a linha colorida estoura a coluna que a monocromática cabe.
Papéis, não cores
Um theme mapeia papel → estilo: accent 179, added/ok 32, removed/error 31, warn 33, danger 1;97;41, dim 2, cursor 7. Em monocromático o mapa devolve lipgloss.NewStyle() vazio — nenhum escape sai.
Relógio
tea.Tick de ~120 ms só enquanto há turno rodando — move spinner e tempo decorrido. Ocioso, nenhum tick: tela parada não repinta.
