# Planning: Conjunto de Ferramentas

> Contrato técnico. Use **EXATAMENTE** os nomes, campos e tipos definidos aqui.
> Regra de negócio em `202608072337-tool-suite.r.spec.md`.

## 1. Nível de estabilidade

**`experimental`** como código interno (`internal/tools`), mas **os nomes de ferramenta e seus campos de input são `stable` desde já** — entram no schema enviado ao modelo, e os limiares dos contratos comportamentais do loop e do provider foram medidos contra eles. Renomear campo invalida limiar e exige nova medição.

## 2. Interface

```go
// Package: internal/tools

type Tool interface {
    Name() string
    Description() string
    Schema() json.RawMessage

    // Declare informa à política o que esta chamada tocaria, SEM executar (RN-6).
    Declare(input json.RawMessage) (policy.Request, error)

    // Execute só é chamado após veredito favorável.
    Execute(ctx context.Context, input json.RawMessage, s *State) (Result, error)
}

type Result struct {
    Output    string
    IsError   bool
    Truncated bool
    Remaining int // bytes não devolvidos quando Truncated (RN-5)
}
```

> `Declare` separado de `Execute` é o que torna RN-6 estrutural em vez de disciplinar: a política decide sobre uma declaração, antes de qualquer efeito.

## 3. Rastreamento de arquivos lidos

```go
// State implementa a invariante read-before-edit (RN-3) e é o estado de sessão
// que toda ferramenta recebe.
type State struct{ /* ... */ }

// fileState é o registro por arquivo, e é NÃO EXPORTADO de propósito: nada
// fora do pacote precisa dele, e exportá-lo convidaria um chamador a montar um
// à mão — que é exatamente como a invariante de leitura prévia se contorna
// sem ninguém perceber.
type fileState struct {
    hash   string // SHA-256 do conteúdo no momento da leitura
    readAt int    // índice da mensagem no histórico — NÃO timestamp (RN-7)
}

func (s *State) MarkRead(path, content string, msgIdx int)
func (s *State) CheckEditable(path, current string) *ToolError
func (s *State) MarkWritten(path string)
func (s *State) Written() []string
func (s *State) ReadPaths() []string
func (s *State) ChangedSinceRead(read func(path string) (string, error)) []string
```

> **Correção de nome.** Esta seção dizia `SessionFiles` e `FileState`, e o código sempre implementou `State` e `fileState`. A regra de ouro do `.p` é usar exatamente estes nomes, então a divergência tornava a spec impossível de seguir ao pé da letra — e quem tentasse escreveria código que não compila.
>
> Vence o nome do código, e por uma razão além da inércia: o tipo deixou de ser só "os arquivos da sessão" quando ganhou plano, caminhos escritos e caminhos lidos. `SessionFiles` descreveria hoje menos da metade dele.
>
> `CheckEditable` devolve `*ToolError` e não `error`, porque quem chama precisa do `code` para montar o resultado — e um `error` genérico obrigaria cada chamador a fazer type assertion de volta.

`CheckEditable` devolve erro distinto para cada caso:

| Situação | `code` | Mensagem ao modelo |
|---|---|---|
| Nunca lido nesta sessão | `file_not_read` | leia o arquivo antes de editar |
| Hash difere do lido | `file_changed` | o arquivo mudou desde a leitura; releia |

> `ReadAt` guarda índice de mensagem, não horário. Timestamp aqui vazaria para o resultado e invalidaria o cache (RN-7).

## 4. As ferramentas

### 4.1 `read`

```go
type ReadInput struct {
    Path   string `json:"path"`
    Offset int    `json:"offset,omitempty"` // linha inicial, base 1
    Limit  int    `json:"limit,omitempty"`  // máximo de linhas
}
```

- Saída numerada por linha, para que `edit` e o modelo falem do mesmo referencial.
- Default de `Limit`: `ReadMaxLines`. Excedido, trunca e declara (RN-5).
- Sucesso chama `MarkRead` com o conteúdo **integral do trecho lido**.
- Arquivo binário não é despejado: devolve tipo e tamanho.
- `Declare`: leitura de `Path`.

### 4.2 `write`

```go
type WriteInput struct {
    Path    string `json:"path"`
    Content string `json:"content"`
}
```

- Arquivo inexistente: cria, incluindo diretórios intermediários.
- Arquivo existente: exige `CheckEditable` (RN-8). Mesma invariante de `edit`.
- Escrita atômica: arquivo temporário no mesmo diretório, depois `rename`.
- `Declare`: escrita em `Path`.

### 4.3 `edit`

```go
type EditInput struct {
    Path       string `json:"path"`
    OldString  string `json:"old_string"`
    NewString  string `json:"new_string"`
    ReplaceAll bool   `json:"replace_all,omitempty"`
}
```

**A ferramenta mais crítica do conjunto.**

- `CheckEditable` antes de qualquer coisa (RN-3).
- `OldString` ausente → erro `no_match`.
- `OldString` aparecendo N vezes com `ReplaceAll = false` → erro `ambiguous_match` **informando N** (RN-4). Não substitui nada.
- `ReplaceAll = true` substitui todas e informa quantas.
- `OldString == NewString` → erro; é sempre engano.
- Escrita atômica; `MarkRead` atualizado com o novo conteúdo, para que a próxima edição funcione sem releitura.
- `Declare`: escrita em `Path`.

### 4.4 `glob`

```go
type GlobInput struct {
    Pattern string `json:"pattern"`
    Path    string `json:"path,omitempty"` // raiz; default workspace
}
```

- Ordenação **determinística**, alfabética. Nunca ordem do sistema de arquivos, que varia por máquina e quebraria golden.
- `Path` apontando para **arquivo** busca naquele arquivo, não devolve vazio.
- Respeita `.gitignore` por default.
- Limitado a `GlobMaxResults`; excedido, trunca e declara.
- `Declare`: leitura de `Path`.

### 4.5 `grep`

```go
type GrepInput struct {
    Pattern     string `json:"pattern"`      // expressão regular
    Path        string `json:"path,omitempty"`
    Glob        string `json:"glob,omitempty"`
    ContextLines int   `json:"context_lines,omitempty"`
}
```

- Saída `caminho:linha:conteúdo`, ordenada por caminho e depois por linha.
- `Path` apontando para **arquivo** busca naquele arquivo. Estreitar para um arquivo é o movimento seguinte natural de quem achou demais, e devolver "nenhuma ocorrência" ali é relato confiante de ausência — o único tipo de resposta errada que ninguém reconfere.
- Limitado a `GrepMaxMatches`; excedido, trunca e declara.
- Regex inválida é erro claro, não pânico.
- `Declare`: leitura de `Path`.

### 4.6 `symbol`

```go
// SymbolInput é a forma do argumento.
type SymbolInput struct {
    // Name é o símbolo. NÃO é expressão regular: é escapado antes de virar
    // padrão. Aceitar regex aqui reintroduziria o problema pela porta dos
    // fundos e faria `symbol` ser `grep` com outro nome.
    Name string `json:"name"`
    Kind string `json:"kind,omitempty"` // "def" | "ref" | "any"; default "any"
    Path string `json:"path,omitempty"`
    Glob string `json:"glob,omitempty"`
}

const (
    KindDef = "def"
    KindRef = "ref"
    KindAny = "any"
)

// SymbolLimit acompanha TODO resultado, sempre.
const SymbolLimit = "textual match on symbol boundary; does not resolve interface or dynamic dispatch"
```

Saída em `path:line:text`, ordenada, com cabeçalho de contagem e a declaração de limite. Nunca o arquivo inteiro.

`declPatterns` é a tabela de padrões de declaração por extensão, **dado do pacote**. Extensão ausente da tabela não é erro: cai na busca por fronteira de palavra, e o resultado reporta `kind unknown` nomeando as extensões que não soube classificar.

> O que justifica a oitava ferramenta não é a fronteira de palavra — `\bParse\b` já é expressável no `grep`, que aceita regex Go. É a distinção entre **definição e uso**, que exige saber como cada linguagem declara. Isso é conhecimento que a ferramenta carrega como dado, em vez de o modelo reconstruir por linguagem toda vez.

### 4.7 `explore`

```go
// Delegator roda um sub-turno somente-leitura. Interface pelo mesmo motivo que
// `Bash` recebe `Runner`: o laço é dono de turno e este pacote é dono de
// ferramenta, e qualquer um importar o outro fecharia ciclo.
type Delegator interface {
    Explore(ctx context.Context, task, path string) (conclusion string, read, unread []string, truncated bool, err error)
}

// ExploreInput é a forma do argumento.
//
// NÃO há campo de modo, e essa ausência é a garantia: somente-leitura é fixado
// onde o sub-turno é construído, então não é algo que o modelo passa nem algo
// que um chamador esquece.
type ExploreInput struct {
    Task string `json:"task"`
    Path string `json:"path,omitempty"`
}
```

O resultado carrega conclusão, **caminhos lidos** e **o que não pôde ser lido**. Os dois últimos nunca são omitidos: não provam que o filho entendeu, provam que olhou, e transformam "confie em mim" em algo conferível por amostragem.

O registro do filho é **lista de permissão** — `read`, `glob`, `grep`, `symbol` — e não lista de bloqueio. Ferramenta acrescentada depois fica de fora até alguém pensar nela, que é o lado seguro de errar. `explore` não está nele: aninhamento é impossível, não proibido.

### 4.8 `bash`

```go
type BashInput struct {
    Command string `json:"command"`
    Timeout int    `json:"timeout_seconds,omitempty"`
}
```

- Executa **sempre** dentro do sandbox, envolvido por `sandbox.Wrap`.
- Diretório de trabalho é o workspace.
- `stdout` e `stderr` combinados, limitados por `MaxToolOutput` do protocolo.
- Código de saída diferente de zero **não** é erro de ferramenta: é resultado, com o código incluído. O modelo precisa dele para decidir (RN-4 do loop).
- Timeout devolve o que já saiu, marcado como truncado.
- `Declare`: comando de sistema — sempre serializado pelo loop, nunca em paralelo.

### 4.9 `plan`

```go
type PlanInput struct {
    Items []PlanItem `json:"items"`
}

type PlanItem struct {
    ID      int    `json:"id"`
    Text    string `json:"text"`
    Status  string `json:"status"`            // pending | active | done | blocked
    Blocked string `json:"blocked,omitempty"` // motivo; obrigatório quando status == blocked
}
```

- Substitui o plano inteiro a cada chamada — mais simples e idempotente que aplicar deltas.
- **No máximo um item `active`.** Mais de um é erro `plan_multiple_active`.
- `status == "blocked"` sem `Blocked` preenchido é erro `plan_blocked_no_reason`: bloqueio sem causa visível é pior que nenhum bloqueio.
- Emite `plan.updated`.
- `Declare`: **nenhum caminho, nenhuma rede.** O veredito da política é sempre `allow`; `plan` nunca cruza fronteira.
- Profundidade é decisão do modelo, proporcional à tarefa — ver `202608080016-behavior-definition`.

## 5. Códigos de erro

| `code` | Ferramenta | Recuperável pelo modelo |
|---|---|---|
| `file_not_read` | edit, write | sim — ler primeiro |
| `file_changed` | edit, write | sim — reler |
| `no_match` | edit | sim — reler e ajustar |
| `ambiguous_match` | edit | sim — mais contexto ou `replace_all` |
| `no_op_edit` | edit | sim — `old` e `new` idênticos |
| `not_found` | read, glob, grep | sim |
| `is_binary` | read | sim |
| `invalid_pattern` | grep, glob | sim |
| `timeout` | bash | sim |
| `plan_multiple_active` | plan | sim — marcar só um |
| `plan_blocked_no_reason` | plan | sim — informar o motivo |
| `denied` | qualquer | não — decisão do usuário |

Todos, exceto `denied`, viram `ToolError` recuperável no loop e alimentam a reanálise do modelo.

## 6. Invariantes verificáveis

- `edit` em arquivo não lido **sempre** falha com `file_not_read`, mesmo que o caminho exista e o trecho case.
- `edit` após modificação externa falha com `file_changed`.
- `edit` com trecho aparecendo duas vezes e `ReplaceAll = false` **não altera o arquivo** e informa `2`.
- `edit` bem-sucedido atualiza o hash; segunda edição seguida funciona sem releitura.
- `write` sobre arquivo existente não lido falha (RN-8).
- Escrita é atômica: falha no meio não deixa arquivo parcial — verificado interrompendo entre temporário e `rename`.
- `glob` devolve a mesma ordem em execuções repetidas e em máquinas distintas.
- Toda ferramenta implementa `Declare` sem qualquer efeito colateral — verificado com espião no sistema de arquivos.
- Nenhuma saída contém timestamp ou caminho absoluto que varie por máquina, salvo quando é a informação pedida (RN-7) — **inclusive em erro**, que é o que o modelo lê com mais atenção.
- `read` em diretório diz que é diretório e aponta `glob`; nunca devolve o erro do sistema de arquivos cru.
- Truncamento sempre acompanha `Truncated = true` e `Remaining > 0` (RN-5).
- `bash` com saída diferente de zero devolve `IsError = false` e o código no output.
- Nenhuma ferramenta executa sem veredito favorável da política (RN-6).
- `plan` com dois itens `active` falha e **não** altera o plano vigente.
- `plan` com item `blocked` sem motivo falha e não altera o plano vigente.
- `plan.Declare` não reporta caminho nem rede; o veredito é sempre `allow`.
- `edit` com `ReplaceAll` afetando mais de uma ocorrência devolve o diff no output do modelo (RN-9).
- `edit` de ocorrência única **não** devolve diff no default; o output é a contagem.
- `write` nunca devolve diff no output, em nenhum valor de `EditEchoDiff`.
- Diff devolvido acima do teto declara o truncamento — varredura da saída.
- `grep`, `glob` e `symbol` com `Path` de arquivo buscam nele; o caminho relatado é o do arquivo, não `.`.
- `symbol` escapa `Name`: `"a.b"` não casa `axb` (RN-10).
- `symbol` respeita fronteira: `Parse` não casa em `ParseTOML` nem `parseMode`.
- `kind: "def"` em `.go` casa `func Parse(` e não casa a chamada `Parse(`.
- Extensão sem padrão conhecido devolve resultado com `kind` desconhecido, nunca erro.
- Todo resultado de `symbol` carrega a declaração de limite textual — varredura.
- Ordenação de `symbol` estável entre execuções e entre máquinas.
- `explore` recebe a tarefa e **não** o histórico do pai — asserção sobre a entrada (RN-11).
- Resultado de `explore` sempre carrega a lista de caminhos lidos, mesmo quando vazia.
- `explore.Declare` reporta leitura, nunca escrita nem rede.


## Contratos comportamentais

> Seção presente porque a RN-9 introduz comportamento mediado. O resto desta spec é determinístico: *quando* o diff volta é asserção, e a tabela de `echoDiff` cobre. O que não se assegura por teste é o modelo **olhar** o que voltou.
