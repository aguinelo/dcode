# Planning: Cliente TUI

> Contrato técnico. Use **EXATAMENTE** os nomes, campos e tipos definidos aqui.
> Regra de negócio em `202608081250-client-tui.r.spec.md`.

## 1. Nível de estabilidade

**`experimental`** para o código (`internal/tui`).

**`stable` desde a primeira versão publicada** para os **atalhos de teclado** e para os **nomes dos comandos embutidos**. Usuário desenvolve memória muscular; remapear depois é custo direto para quem já usa.

### 2.1 Geometria

| Região | Largura | Altura |
|---|---|---|
| Status | total | 1 |
| Fluxo | total − painel | restante − 2 |
| Painel | `PanelWidth` (default 24) | igual ao fluxo |
| Entrada | total − painel | 1 |

**Colapso responsivo (RN-5):** largura total < `PanelMinTotalWidth` (default 100) esconde o painel e move o contador para o status. Reversível ao alargar.

A preferência explícita do usuário tem precedência sobre a automática **em ambos os sentidos**, o que exige três estados e não um booleano:

```go
type PanelMode int

const (
    PanelAuto   PanelMode = iota // largura decide — default
    PanelShown                   // o usuário pediu, em qualquer largura
    PanelHidden                  // o usuário dispensou, em qualquer largura
)
```

Um booleano `PanelHidden` não expressa isso: partindo de `auto` não há flag para inverter, e a tecla vira no-op exatamente no terminal estreito onde o usuário foi procurá-la.

**O painel encolhe antes de sumir.** Largura efetiva = `PanelWidth` limitada a um quarto da tela, com piso em `PanelMinWidth` (default 16). A 80 colunas isso troca quatro células do painel por quatro do stream, que é o sentido certo: o painel tem linhas curtas, o stream tem diff.

**Painel colapsado se anuncia.** O status carrega o contador **e** a tecla que o traz de volta. Colapsado em silêncio é indistinguível de quebrado, e a tecla só está documentada dentro do próprio painel.

## 3. Renderização do fluxo

### 3.1 Chamada de ferramenta — uma linha

```
⏺ <ferramenta>  <alvo>  <resumo>
```

| Ferramenta | Alvo | Resumo |
|---|---|---|
| `read` | caminho | `240 linhas` ou `240 linhas (truncado)` |
| `edit` | caminho | `+24 −2` |
| `write` | caminho | `criado` ou `+120 −118` |
| `glob` | padrão | `18 arquivos` |
| `grep` | padrão | `18 ocorrências em 4 arquivos` |
| `bash` | comando, truncado | `✓ saída 0` ou `✗ saída 1` |
| `plan` | — | `5 itens` ou `item 3 concluído` |

**Estado de expansão (RN-3):** sucesso recolhido, erro **expandido**. `Tab` alterna o item sob o cursor.

**O resumo vem do metadado, nunca do texto.** A ferramenta reporta `lines`,
`files`, `added`, `removed`, `exit_code` e `duration_ms` no evento; o cliente lê
esses campos. Reconstruir o número casando prosa quebra no dia em que a redação
muda, e quebra em todo cliente ao mesmo tempo.

Duração só aparece a partir de 500ms. Toda chamada carregando tempo transforma a
coluna em ruído que ninguém lê.

### 3.2 Diff — é o que se revisa (US-5)

`edit` e `write` sobre arquivo existente renderizam diff compacto: até `DiffContextLines` de contexto, adição e remoção marcadas, truncado em `DiffMaxLines` com contador do que sobrou.

Nunca o conteúdo integral do arquivo — o que se revisa é a mudança.

### 3.3 Erro de ferramenta

Expandido, com `Reason` em destaque e `Hint` logo abaixo quando houver. O `Hint` é o que o modelo vai usar para se recuperar; o usuário se beneficia de ver o mesmo sinal.

## 4. Painel de plano

Alimentado por `plan.updated` do protocolo. **O TUI não deriva plano de texto** — se o painel precisasse interpretar prosa, qualquer outro cliente teria que reimplementar a mesma heurística.

```go
// Package: internal/tui

type PlanItemStatus string

const (
    PlanPending  PlanItemStatus = "pending"
    PlanActive   PlanItemStatus = "active"
    PlanDone     PlanItemStatus = "done"
    PlanBlocked  PlanItemStatus = "blocked"
)
```

| Status | Marca |
|---|---|
| `pending` | ` ` |
| `active` | `▸` |
| `done` | `✓` |
| `blocked` | `⊘` + motivo na linha seguinte (RN-4) |

Rodapé do painel: `<concluídos> de <total> · <bloqueados> bloqueado`. **É o mesmo texto que vai para o status quando o painel colapsa** — uma formulação só, para não divergirem.

Plano maior que a altura disponível rola para manter o item `active` visível. Nunca esconde item `blocked` sem indicar que existe.

## 5. Linha de status

```
● dcode  <modelo>  <modo-sandbox>  ctx <pct>%  $<custo>  [<plano>]
```

| Campo | Origem | Observação |
|---|---|---|
| Indicador | estado da sessão | `●` ocioso, `◐` trabalhando (animado), `⏸` bloqueado |
| Modelo | `Session.Model` | |
| **Modo de sandbox** | `Session.SandboxMode` | **indicador de segurança** — ver abaixo |
| Contexto | tokens ÷ janela | destaque ao cruzar o limiar de compactação |
| Custo | `Usage` acumulado | |
| Plano | rodapé do painel | só quando o painel está colapsado |

**Modo de sandbox não é informação, é indicador de segurança.** É o único estado em que estar errado é perigoso, e funciona como o cadeado do navegador. `full-access` é renderizado com destaque de alerta, sempre. Alguém rodando irrestrito sem perceber é incidente esperando acontecer.

## 6. Aprovação

Modal sobreposto, centralizado, **bloqueando a entrada** (RN-6).

```
┌─ Aprovação necessária ──────────────────────────┐
│                                                 │
│  O agente quer acessar a rede                   │
│                                                 │
│    curl -X POST https://api.exemplo.com/v1      │
│                                                 │
│  Fronteira cruzada: network                     │
│  Modo atual: workspace-write                    │
│  Expira em: 1m48s                               │
│                                                 │
│  [n] Negar    [s] Permitir    [S] Toda a sessão │
│                                                 │
└─────────────────────────────────────────────────┘
```

| Regra | Motivo |
|---|---|
| `Enter` = negar | ação segura é a de menor esforço |
| `ApprovalRequest.Command` renderizado | descrição sem comando é consentimento cego |
| `S` maiúsculo para sessão inteira | maior consequência, mais difícil por acidente |
| Contagem regressiva visível | expirar nega (RN-5 do protocolo); o usuário precisa saber |
| Modal **não** mostra o plano | RN-7; aprovar plano não é aprovar fronteira |

## 7. Atalhos — `stable`

| Tecla | Ação |
|---|---|
| `Enter` | enviar, ou confirmar o default do modal |
| `Ctrl+C` | interromper o turno; ocioso, sai |
| `Ctrl+D` | sair |
| `Esc` | fechar expansão, depois a seleção, depois o modal |
| `↑` `↓` | **linha vazia:** histórico · **linha com texto:** cursor no fluxo |
| `PgUp` `PgDn` | rolar uma tela, com duas linhas de sobreposição |
| `Home` `End` | início da sessão · fim, religando o acompanhamento |
| `Tab` | alternar expansão do item sob o cursor |
| `Ctrl+P` | alternar painel |
| `Ctrl+A` `Ctrl+E` | início e fim da linha |
| `Ctrl+W` `Ctrl+U` `Ctrl+K` | apagar palavra · limpar linha · cortar até o fim |
| `←` `→` `Del` | mover o caret · apagar sob ele |
| `?` | ajuda, apenas em linha vazia |

**Letra nunca é atalho (RN-16).** Numa linha em que se digita, atalho é tecla de
controle ou pontuação. `p` era o atalho do painel e comia a primeira letra de
`primeiro`, `please`, `por favor`. Ver `changelog/202608082330-*`.

**Sobre `↑` `↓`:** a leitura barata de errar é a escolhida. Com texto na linha, o
histórico destruiria o que está sendo escrito; com a linha vazia, mover o cursor
no fluxo não custa nada ao usuário que queria o histórico — ele aperta de novo.

## 7.1 Rolagem e acompanhamento

**RN-12.** O fluxo acompanha a saída mais nova por default. Rolar para cima
desliga; voltar ao fim religa. Com o acompanhamento desligado, saída nova **não
move o que está na tela** — ler algo enquanto o fluxo o empurra para fora é a
coisa mais irritante que um log ao vivo faz.

**RN-13.** Fora do fim, o cliente diz quantas linhas há abaixo e como voltar.
Tela pausada em silêncio é indistinguível de agente travado: nos dois casos a
tela para de mudar.

O cursor puxa a janela para si. Mover uma seleção que não se vê é como uma tecla
parece quebrada: algo aconteceu e nada mudou na tela.

## 7.2 Indicador de processamento — `stable`

**RN-14.** Enquanto o turno roda:

```
⠹ bash go test ./...  12.4s  1.2k tok  ^C interrompe
```

| Campo | Origem |
|---|---|
| Indicador animado | contador de quadro, não relógio — `Render` continua pura |
| O que roda | última ferramenta ainda sem resposta, ou `working` |
| Tempo decorrido | medido **pelo cliente** desde `turn.started` |
| Custo até aqui | `Usage` acumulado |
| Como parar | sempre visível, ao lado do que se quer parar |

Tempo é do cliente porque precisa avançar entre eventos; carimbo do servidor só
está certo no instante em que chega. O quadro só avança com turno rodando: tela
ociosa repintando gasta bateria sem informar nada.

## 7.3 Cor — `stable`

**RN-15.** Cor é informação, nunca decoração. Papéis, não cores: `dim`, `bold`,
`accent`, `added`, `removed`, `error`, `warn`, `ok`, `danger`, `cursor`.

- Desligada, **nada de conteúdo se perde**. `full-access` muda o texto além da
  cor, porque é o único estado em que estar errado é perigoso.
- `NO_COLOR` e `TERM=dumb` desligam. `DCODE_COLOR` (`always`/`never`) decide
  sobre os dois: é o usuário respondendo pelo próprio terminal.
- Estilo **nunca** altera largura medida. Toda medida é em células de exibição,
  com os escapes descontados — senão a linha colorida estoura a coluna que a
  monocromática cabe, e o defeito não aparece em captura de tela.
- Monocromático **não emite escape algum**, nem de reset.

`Ctrl+C` interrompe antes de sair porque interromper é o que se quer na esmagadora maioria das vezes; sair por acidente no meio de um turno é perda de trabalho.

## 8. Comandos embutidos — `stable`

| Comando | Ação |
|---|---|
| `/help` | atalhos e comandos |
| `/init` | cria `DCODE.md` no workspace a partir do que já existe |
| `/clear` | encerra a sessão e abre outra |
| `/plan` | mostra o plano completo; força replanejamento com argumento |
| `/config <chave>` | valor efetivo **e** procedência |
| `/model <nome>` | troca de modelo — abre sessão nova, pois muda o prefixo |
| `/resume` | lista sessões e reconecta |

Comandos do usuário, descobertos conforme a spec de configuração, não podem sobrescrever nome embutido. Colisão é registrada e o embutido vence.

> `/loop` e `/goal` **não** entram aqui: alteram a terminação do laço de turno, não a interface. Pertencem à spec do loop.

## 8.1 Estado vazio

Sessão nova sem turno exibe o mascote (`docs/brand/mascot.svg`, em meia-altura de bloco),
o nome, a versão, e a linha de atalhos essenciais.

```
        ▄▄▄▄
        █▀▀█        dcode 0.1.0
        ████
      ▄▄▄▄▄▄▄▄      MiniMax-M3 · workspace-write
      ████████
    ▄▄▄▄▄▄▄▄▄▄▄▄    ? ajuda   ^C interromper
    ████████████
     ▀▀      ▀▀

  › _
```

- Degrada para ASCII quando `Unicode` está desligado, e para uma cor com `Color=never`.
- **Desaparece no primeiro turno** e não volta enquanto a sessão viver (RN-10).
- Nunca exibido quando a sessão é retomada com histórico.

## 9. Fila de entrada

```go
type InputQueue interface {
    Push(text string)
    PopAll() []string
}
```

Estado **local do cliente** (RN-11). Submetida quando a sessão volta a `idle`. Múltiplas mensagens enfileiradas são unidas em um turno, na ordem de digitação — não viram turnos separados, o que violaria a regra de um turno por sessão.

Item na fila é visível acima da entrada, e removível antes do envio.

## 10. Invariantes verificáveis

- Renderização é pura sobre estado da sessão e geometria: mesma entrada, mesma saída byte-a-byte.
- Nenhum estado de sessão vive no cliente (RN-11) — só rolagem, visibilidade do painel e fila.
- Fechar e reabrir reproduz a sessão a partir de `from=1` e chega ao mesmo estado visual.
- Sucesso vem recolhido, erro vem expandido, sem exceção.
- Diff nunca renderiza o conteúdo integral do arquivo.
- Painel colapsa abaixo de `PanelMinTotalWidth` e restaura ao alargar.
- `PanelShown` exibe o painel em qualquer largura; `PanelHidden` o esconde em qualquer largura (RN-5).
- Plano vazio não exibe painel em modo algum — painel vazio é pior que painel nenhum.
- Painel colapsado com plano vivo põe contador e tecla no status.
- Largura do painel nunca passa de um quarto da tela nem cai abaixo de `PanelMinWidth`.
- Preferência explícita do usuário vence a automática nos dois sentidos.
- Contador do painel e contador do status usam a **mesma** formulação.
- Item `blocked` nunca é escondido sem indicação de que existe.
- Modal de aprovação bloqueia a entrada e tem negar como default.
- Modal renderiza `ApprovalRequest.Command` quando presente.
- Modal **não** exibe o plano (RN-7).
- `full-access` é sempre renderizado com destaque de alerta.
- Entrada durante turno ativo entra na fila, nunca é submetida ao servidor.
- Fila com N mensagens produz **um** turno, na ordem de digitação.
- `Ctrl+C` durante turno interrompe; durante ociosidade não sai na primeira vez.
- Comando de usuário não sobrescreve embutido; colisão registrada.
- Estado vazio some no primeiro turno e não reaparece na mesma sessão.
- Sessão retomada com histórico nunca exibe o estado vazio.
- O mascote degrada para ASCII e para uma cor sem perder as três caixas.
