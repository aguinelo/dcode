# Neon

**Data:** 2026-08-24
**Specs afetadas:** `202608081250-client-tui` (`.p`, seção 10)
**Fonte:** design `Coding Agent TUI v2`, tema `neon` (o principal)

## O que mudou

A interface tem paleta própria, com **fundo próprio**.

Até aqui os papéis mapeavam para um punhado de códigos ANSI escolhidos para
caber educadamente dentro do tema que o terminal já tivesse. Essa educação é o
que fazia a tela ler como cinza: três pesos e um âmbar, sobre um fundo que o
produto não escolheu, não é paleta — é a ausência de uma.

## O fundo é a decisão

Não é de graça: a interface deixa de herdar as cores do terminal e passa a
possuí-las. É o que o design pede, e é o que faz um acento ser acento — âmbar
sobre fundo desconhecido é uma cor; âmbar sobre `#120d24` é um sinal.

Cor desligada não recebe nada disso. `Palette{}` continua não emitindo escape
nenhum, fundo incluído, e há teste afirmando que **nenhum `0x1b` chega à tela**
nesse caminho. Não é uma segunda implementação: é o mesmo código com a tabela
vazia.

## Uma regra minha de hoje de manhã foi revogada

O invariante dizia: *"papel de texto usa só os pesos que um terminal mantém
sobre fundo desconhecido — nunca um cinza cravado"*, porque um cinza escolhido
para tema escuro é ilegível em tema claro.

Isso valia exatamente enquanto o produto **não escolhia o fundo**. Agora escolhe.
A restrição deixou de ser "não escolha cor" e passou a ser "**escolha uma que se
leia contra o fundo que você escolheu**" — que é afirmação mais forte, e
mensurável. O teste mede contraste WCAG: 4.5 para o que se lê, 3 para o que se
destaca, 1.5 para cromo.

## Um desvio do design, com a medida

O `--bd` do design é `#2a1f4a`, que mede **1.26:1** contra este fundo. É certo
para uma linha de um pixel numa superfície iluminada por três gradientes
radiais; uma régua de terminal é uma fileira de glifos sólidos sobre fundo
plano, e a 1.26:1 ela não está lá.

O cromo usa o `dim3` do próprio design, `#4a3f70`, a **2.02:1** — visível, e
ainda quieto o bastante para não competir com o que separa.

## Fechar o que se abriu

A primeira versão fechava cada trecho com `\e[0m`, o que desfaz o **fundo**
também — então cada palavra abria um buraco nele, remendado repintando o fundo
depois de cada reset. Funcionava e custava um escape de fundo inteiro por
palavra: numa tela de 100 colunas de prosa, triplicava os bytes de cada quadro,
repintado a cada 120 ms.

Fechar só o que foi aberto (`22`, `39`, `49`) custa quatro bytes e deixa o fundo
da linha em paz. O quadro colorido ficou em **2.3×** o monocromático.

## Profundidade

Truecolor por padrão, com o cubo de 256 como alternativa — e **não** dezesseis:
metade desta paleta é texto violeta-acinzentado sobre fundo violeta, e dezesseis
cores não desenham nem um nem outro. Terminal abaixo de 256 recebe o caminho sem
cor, que é uma tela em que este produto é testado.

Os cinzas importam mais que os matizes aqui, então o mapeamento tem rampa de
cinza própria: cinza empurrado para dentro do cubo volta levemente esverdeado.

## O guarda de cor achou um defeito

`renderToolLine` media a calha com `len()` — bytes, não células. Com escapes
maiores, o alvo encolhia **só no terminal com cor**, que é a espécie mais difícil
de defeito de enxergar. `TestColourNeverChangesWhatIsOnTheScreen` o pegou na
primeira execução com o tema ligado. É exatamente para isso que ele existe.
