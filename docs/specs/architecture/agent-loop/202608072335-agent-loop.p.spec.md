# Planning: Loop do Agente

> Contrato técnico. Use **EXATAMENTE** os nomes, campos e tipos definidos aqui.
> Regra de negócio em `202608072335-agent-loop.r.spec.md`.

## 1. Nível de estabilidade

**`experimental`.** Vive em `internal/loop`. Não é superfície pública — o que é público é o protocolo (`202608072240-client-server-protocol`), e o loop se expressa por ele.

## 2. Máquina de estados do turno

```go
// Package: internal/loop

type TurnPhase string

const (
    PhaseAssembling TurnPhase = "assembling" // montando contexto (checagem de compactação)
    PhaseStreaming  TurnPhase = "streaming"  // recebendo do provider
    PhaseExecuting  TurnPhase = "executing"  // executando ferramentas
    PhaseBlocked    TurnPhase = "blocked"    // aguardando aprovação
    PhaseDone       TurnPhase = "done"
)

type StopReason string

const (
    StopDone           StopReason = "done"            // modelo terminou sem tool call
    StopInterrupted    StopReason = "interrupted"     // usuário interrompeu
    StopMaxIterations  StopReason = "max_iterations"  // teto atingido
    StopRepeatLoop     StopReason = "repeat_loop"     // detector de repetição
    StopMaxTokens      StopReason = "max_tokens"      // orçamento de token
    StopError          StopReason = "error"           // erro não recuperável
)
```

Transições válidas:

```
assembling ──▶ streaming ──┬──▶ done                    (sem tool call)
     ▲                     └──▶ executing ──┬──▶ assembling   (próxima iteração)
     │                                      └──▶ blocked ──▶ executing
     └──────────────────────────────────────────┘
qualquer fase ──▶ done   (interrupção ou erro)
```

## 3. Limites

```go
type Limits struct {
    MaxIterations   int // default 50
    MaxIdenticalCalls int // default 3
    MaxTurnTokens   int // default 0 = ilimitado
}
```

**Por que 50 iterações.** Dimensionado pelo caso legítimo: refactor cruzando dez arquivos consome de trinta a cinquenta chamadas. Teto de dez quebraria trabalho real (RN-2).

**Por que o detector é o mecanismo real.** Loop patológico aparece em três repetições, muito antes de cinquenta. O teto é backstop.

```go
// IsRepeat compara ferramenta E input canonicalizado.
// Input diferente NÃO é repetição — é o que permite RN-4 (tentar
// abordagem alternativa) conviver com o detector.
func IsRepeat(history []ToolCall, n int) bool
```

Canonicalização do input: JSON com chaves ordenadas, sem espaço em branco irrelevante. Sem isso, reordenar chaves escaparia do detector.

**Por que o teto de token não é a defesa primária.** Cortar por token no meio do turno para o agente com o workspace meio-editado. O teto de iterações já limita o gasto por construção: cinquenta iterações são o teto real. `MaxTurnTokens` existe para quem precisa de controle duro de custo.

## 4. Execução de ferramentas

```go
type ToolExecution struct {
    Index      int       // posição na emissão do modelo — define a ordem de anexação
    Call       ToolCall
    StartedAt  time.Time // ordem REAL de execução, para o log
    FinishedAt time.Time
    Result     ToolResult
}
```

### 4.1 Paralelismo e ordem

**Anexação:** sempre por `Index` crescente, nunca por ordem de término (RN-3.1). É o que mantém o histórico reproduzível.

**Execução:** concorrente, exceto onde a seção 4.2 exige serialização.

**Log:** `StartedAt` e `FinishedAt` registram a ordem real (RN-3.3). Eles vivem no evento, **nunca** no contexto enviado ao modelo — timestamp no prefixo violaria a ADR-03.

### 4.2 Regra de conflito

Serializam entre si, na ordem de `Index`:

| Condição | Motivo |
|---|---|
| Duas chamadas que escrevem o mesmo caminho | resultado dependeria de corrida |
| Uma escrita e uma leitura do mesmo caminho | leitura veria estado indefinido |
| Duas execuções de comando de sistema | efeito colateral arbitrário e não isolável |
| Qualquer chamada que exija aprovação | decisão do usuário é sequencial por natureza |

Só correm em paralelo chamadas comprovadamente independentes — leitura de caminhos distintos e busca. É onde está o ganho real e onde é seguro.

### 4.3 Aviso ao modelo

Quando mais de uma ferramenta executa em paralelo num mesmo passo, o resultado anexado é precedido de nota fixa informando que a execução foi concorrente e que a ordem dos resultados **não** reflete ordem temporal (RN-3.2).

O texto é **constante** — nunca contém timestamp, contagem nem ID. Texto variável aqui invalidaria o cache a cada passo.

### 4.4 Formato do resultado de erro

Para o modelo decidir entre seguir, repetir ou trocar de abordagem (RN-4), o erro carrega:

```go
type ToolError struct {
    Tool     string // o que foi chamado
    Reason   string // o que falhou, em linguagem direta
    Detail   string // sinal disponível: stderr, código de saída, caminho
    Hint     string // opcional; alternativa conhecida, sem prescrever
}
```

`Hint` sugere, não ordena — a decisão é do modelo. Ex.: `"o arquivo não foi lido nesta sessão; leia antes de editar"`.

## 5. Compactação

Verificada **uma vez por iteração**, no passo 2 (RN-6):

1. `contextpkg.Plan(session, cfg)` decide e devolve o plano. Puro.
2. Se há plano, o loop chama o modelo para gerar o resumo do trecho.
3. O loop aplica: substitui o trecho por `Summary`, emite `session.compacted`.
4. Segue para a montagem.

A chamada de resumo **não** conta para `MaxIterations` — é overhead do sistema, não trabalho do agente.

## 6. Interrupção

Pontos de verificação de `ctx.Done()`: entrada de cada fase, cada evento recebido do stream, e após cada ferramenta concluída.

| Momento | Comportamento |
|---|---|
| Em `assembling` | encerra imediatamente; nada foi anexado |
| Em `streaming` | cancela a chamada; texto parcial **é** anexado |
| Em `executing` | ferramenta iniciada é cancelada; **se produziu efeito, o resultado é anexado** (RN-5) |
| Em `blocked` | aprovação é negada; resultado anexado como negado |

Sempre termina com `turn.completed` e `StopInterrupted`. Nunca deixa resultado órfão nem escrita pela metade sem registro.

## 8. Invariantes verificáveis

- Nenhuma transição fora do diagrama da seção 2 é possível; transição inválida retorna erro, nunca `panic`.
- Resultados são anexados em ordem de `Index`, independentemente da ordem de término — verificado com execuções de duração propositalmente invertida.
- Duas chamadas que tocam o mesmo caminho nunca se sobrepõem no tempo (seção 4.2).
- Nenhum comando de sistema executa concorrentemente com outro.
- Nenhuma ferramenta executa sem passar pelo avaliador de política (RN-7).
- Nenhum timestamp, contagem ou ID entra no contexto enviado ao modelo, incluindo a nota da seção 4.3.
- `IsRepeat` é insensível à ordem de chaves do JSON de input.
- `IsRepeat` retorna `false` para mesma ferramenta com input diferente.
- Interrupção em qualquer fase produz exatamente um `turn.completed` com `StopInterrupted`.
- Interrupção durante ferramenta com efeito no disco anexa o resultado.
- Compactação verificada exatamente uma vez por iteração.
- A chamada de resumo não incrementa o contador de iteração.
- Turno que atinge `MaxIterations` termina em `StopMaxIterations`, não em `panic` nem em silêncio.
