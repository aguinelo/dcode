# Config: Distribuição e Atualização

> Nenhuma variável de ambiente nova no código sem estar aqui.
> Precedência: config travada por administrador > flag > variável de ambiente > arquivo de config > default.

> `DCODE_STATE_DIR` é declarada em `202608072240-client-server-protocol.config.spec.md`, seção 1. O cache do aviso de versão vive dentro dela.

## 1. Instalação

Lidas pelo `install.sh`, não pelo binário.

| Variável | Tipo | Default | Uso |
|---|---|---|---|
| `DCODE_VERSION` | string | `latest` | Versão a instalar, ex. `v0.3.1`. Fixar é o caminho para reprodutibilidade (US-5). |
| `DCODE_INSTALL_DIR` | caminho | `$HOME/.local/bin` | Destino do binário. Default gravável pelo usuário, para que a instalação não precise de privilégio elevado. |
| `DCODE_SKIP_VERIFY` | booleano | `false` | **Não existe como opção de conveniência.** Presente apenas para depurar o próprio pipeline de release; o script emite aviso em destaque quando ligada. Usar em instalação real anula a RN-2 e torna o canal um vetor de supply chain. |

## 2. Atualização

| Variável | Tipo | Default | Uso |
|---|---|---|---|
| `DCODE_UPDATE_CHECK` | booleano | `true` | Liga o aviso passivo de versão. Desligar não afeta `dcode update`, que continua funcionando sob demanda. |
| `DCODE_UPDATE_CHECK_INTERVAL` | duração | `24h` | Intervalo mínimo entre consultas. Resultado em cache em `DCODE_STATE_DIR`. Abaixo de `1h` vira ruído de rede sem ganho — a cadência de release não justifica. |
| `DCODE_UPDATE_INSTALLER_URL` | URL | `install.sh` da `main` | De onde o `dcode update` lê o digest que o instalador publicado carrega — a segunda rota, a única que não viaja junto do artefato. Espelho que sobrescreve `DCODE_UPDATE_URL` **precisa sobrescrever este também**, senão a rota independente continua vindo de upstream. |
| `DCODE_UPDATE_URL` | URL | GitHub Releases do projeto | Origem de artefatos e metadados. Existe para espelho corporativo interno (US-4). **A verificação de assinatura continua obrigatória** contra qualquer origem — espelho não é motivo para confiar. |
| `DCODE_RELEASE_CHANNEL` | enum | `stable` | `stable` ou `prerelease`. `prerelease` recebe tag de pré-lançamento; nunca é default e nunca atualiza sozinho (RN-3). |
| `DCODE_UPDATE_CHANNEL` | enum | `stable` | O nome que o código lê. `DCODE_RELEASE_CHANNEL` continua aceita como grafia antiga, e é a única chave do produto com duas. |

## 3. Governança

| Variável | Tipo | Default | Uso |
|---|---|---|---|
| `DCODE_PIN_VERSION` | string | vazio | Trava a versão. Com valor, `dcode update` recusa mudar e explica o pino. Faz sentido principalmente no arquivo de requisitos travado por administrador — ver `202608072336-sandbox-policy.config.spec.md`, seção 3. |

## 4. Constantes não configuráveis

| Constante | Valor | Motivo |
|---|---|---|
| Verificação de SHA-256 na instalação | sempre | RN-2. Independe do cosign. `DCODE_SKIP_VERIFY` é ferramenta de depuração do pipeline, não configuração de usuário. |
| Verificação de assinatura na instalação | quando há cosign | RN-2. Ausente, o script avisa alto e segue. Exigi-lo fazia a falta da verificação forte cancelar a fraca, e o usuário ficava sem binário e sem conferência. |
| Atualização automática | **não existe** | RN-3; um agente que troca o próprio binário sem consentimento anula toda auditoria. |
| Troca de binário por `rename` no mesmo sistema de arquivos | sempre | `rename` entre sistemas de arquivos não é atômico; binário parcial é uma máquina sem dcode. |
| Verificação de execução antes da troca | sempre | Impede substituir binário funcional por um que não roda naquela máquina. |
| Falha de rede no aviso de versão é silenciosa | sempre | RN-4; verificar versão nunca pode degradar o uso. |
| Nome do binário `dcode` | sempre | `stable`; muda instalação documentada em terceiros. |
| Formato do nome de artefato | sempre | `stable`; scripts de terceiros dependem dele. |
